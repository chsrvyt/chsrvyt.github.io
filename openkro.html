Production was down all week. It wasn’t a bug.

Library uploads and downloads had been failing with opaque 500s. The cause turned out to be a credential Google had been quietly expiring every seven days — so the same outage had been recurring, and every previous fix had been a reset of the same clock. Today it got fixed permanently, and the app got faster on the way out.

The actual fault

root cause

Your OAuth consent screen was in “Testing” status. Google force-expires refresh tokens for apps in that state every seven days. The Worker held a dead token, so every Drive call failed — and because the client caught it as a generic error, it surfaced to users as “Please try again”, advice that could never work, since the credential was expired rather than flaky.

  • SYMPTOMLibrary uploads failed; “Couldn’t save Doc for offline viewing”; downloads 500
  • MECHANISMOffline-save fetches the file through /library/:id/file before encrypting it — no bytes, nothing to save
  • FIX 1Minted a fresh refresh token and set it in the Cloudflare dashboard live
  • FIX 2Published the OAuth consent screen to production, removing the 7-day clock live

The first fix alone would have bought seven days. The second is what stops it recurring — worth knowing if this ever looks familiar again.

Build blockers cleared

in order hit

The APK build failed four times before producing anything. Each failure hid the next, so they could only be found one at a time.

  1. A stray static server held a file lockMy own preview process kept out/ open — Next failed with ENOTEMPTY. Killed it; now killed routinely before every build.
  2. Node 20 vs Capacitor 8Capacitor CLI 8.4.2 needs Node ≥ 22; your default is 20.19.5. Builds now run against your installed 24.16.0 via PATH — your global default is untouched.
  3. C: drive completely fullZero bytes free of 277 GB. Gradle cannot unpack into nothing.
  4. Gradle cache on the wrong driveMoved the workspace and GRADLE_USER_HOME to D:. Cold build took 28 min; warm builds now take 2 s.

Disk: cleared ~4 GB of npm cache and temp files. The remaining space came from your end — worth knowing that Steam accounts for 107 GB on C:, and Steam can move a library to D: without re-downloading.
